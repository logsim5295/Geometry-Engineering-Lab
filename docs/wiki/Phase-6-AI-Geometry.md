# Phase 6 · AI + Geometry

[Home](Home.md) · [이전 Phase](Phase-5-Nesting.md)

**목표:** Geometry/Nesting에서 AI가 실제로 시간을 줄이거나 결과를 개선하는지 평가한다. **참고 기간:** 6~8주. **상태:** 전 항목 미착수.

기존 알고리즘 baseline과 재현 가능한 데이터가 준비된 뒤 시작한다. AI가 유리하지 않으면 기존 알고리즘을 유지하는 결론도 유효한 학습 결과다.

## 세부 학습 순서

각 항목을 개념·작은 실험·검증 회차로 나누고 회차당 30~60분을 사용한다.

| 순서 | 개념·실습 | 완료 기준 |
|---|---|---|
| 1 ML 기초 | 학습/추론, 특징, 라벨, 손실, 과적합 | 해결할 문제와 비학습 baseline 설명 |
| 2 Regression / Classification | 후보 점수 예측 vs 개선 가능 후보 분류 | 목표에 맞는 지표(MAE, precision/recall 등) 선정 |
| 3 데이터셋 구성 | 합성 도형·실행 로그·seed | 특징·정답 생성 방법, 학습/검증/평가 분리 기록 |
| 4 Geometry 데이터 분석 | 면적·둘레·종횡비·후보 특성 | 분포·이상치·누락 확인, 단위 통일 |
| 5 배치 후보 예측 | 간단한 모델로 우선순위 산정 | 미사용 테스트 문제에서 baseline과 비교 |
| 6 기존 탐색과 결합 | 상위 후보 평가, 파라미터 탐색 보조 | 예측·정확 검사·학습 데이터 생성 비용까지 비교 |
| 7 CAD 개발 보조 도구 | 테스트 초안·로그 분석·문서 검색 | 제안의 API·계산·결과를 직접 검증 |
| 8 LLM / Agent | 작은 입력→제안→검증 흐름 | 실행 범위를 제한하고 실패 사례·재현 절차 기록 |

## 작은 비교 실험

첫 프로젝트는 후보 점수 예측 또는 탐색 파라미터 선택 중 하나만 고른다. 같은 원본 패턴을 회전한 데이터가 학습·평가 양쪽에 섞이지 않도록 문제 인스턴스/원본 패턴 단위로 분리한다. 작은 데이터에서는 단순 모델과 명시적인 규칙을 우선 비교한다.

AI는 후보 순서나 점수를 제안한다. 최종 충돌·원단 경계·제약 검사는 검증된 기하 알고리즘이 수행한다. 예측 오류가 불가능한 배치를 통과시키지 않도록 한다.

LLM은 개념 설명, 테스트 아이디어, 문서 탐색에 사용한다. 업무·고객 데이터를 실습 데이터로 사용하지 않는다. 모델이 제시한 존재하지 않는 API나 출처는 결과에 포함하지 않는다.
