## 구현과 검증

Geometry-Engineering-Lab의 `01-3D-Math/02-Vector/Vector3D.cs`에 `UnitNormal(v1, v2)`를 구현했다. 입력 영벡터를 거부하고, 두 입력을 먼저 정규화한 뒤 외적의 길이 `|sinθ|`를 `1e-10`과 비교한다. 허용오차 이하이면 예외, 그 외에는 외적을 정규화하여 반환한다. 이 허용오차는 이번 실습에서 선택한 무차원 방향 판정 기준이며 보편적인 정답은 아니다.

| 검증 | 입력 | 확인 결과 | 근거 |
|---|---|---|---|
| 정상 단위 법선 | (2,0,0), (0,3,0) | 외적 (0,0,6), 법선 (0,0,1), 법선 길이 1 | 법선은 학습자 출력 보고, 길이는 앞선 도구 실행 확인 |
| 역순 | (0,3,0), (2,0,0) | 단위 법선 (0,0,-1) | 예상값 제시 후 학습자가 결과 일치를 확인; 전체 콘솔 출력은 미제공 |
| 평행 | (2,0,0), (4,0,0) | ArgumentException 및 catch 메시지 | 앞선 도구 실행 확인 |
| 반평행 | (2,0,0), (-4,0,0) | 외적 길이 0에 대한 예외 | 학습자 출력 보고 |
| 영벡터 | (2,0,0), (0,0,0) | 예외 | 학습자 출력 보고; 최종 코드는 별도의 영벡터 메시지 사용 |
| 거의 평행 | (1,0,0), (1,1e-12,0) | 원본 외적 길이 1E-12, 최종 정책에서 예외 | 학습자 출력 보고 및 도구 재실행 |
| 양의 배율 변경 | (1e6,0,0), (1e6,1e-6,0) | 원본 외적 길이 1, 동일하게 예외 | 코드 확인 및 도구 실행; 학습자 별도 출력 보고는 없음 |

허용오차 적용 전에는 거의 평행한 입력에서도 단위 법선 (0,0,1)을 반환했다. 이는 수학적으로 가능한 결과였다. 최종 구현은 방향의 민감도를 고려해 거의 평행한 입력을 거부하는 정책을 선택했다. 반평행도 `|sinθ|`가 0에 가까워 같은 기준으로 처리한다.

기존 수직성·넓이·평행 퇴화 검증(11월 6일)에 이번 역순 확인과 단위 법선·경계 조건 검증을 합쳐 P1-11을 완료 처리한다. 소스 존재나 AI 실행만으로 새 학습 완료를 인정한 것은 아니다. 두 Wiki의 기존 기준 차이를 유지하여 Geometry-Engineering-Lab은 6/66, OpenCascade-Lab은 4/66으로 기록한다.

## 개념 복습

- 2D `Cross(a,b)=ax*by-ay*bx`는 부호 있는 평행사변형 넓이이자, Z=0으로 확장한 3D 외적의 Z 성분이다. 절댓값의 절반이 삼각형 넓이다. 부호의 좌·우 해석은 X가 오른쪽, Y가 위쪽인 좌표계 기준으로 설명했다.
- `Vector2D.Normalized()`는 벡터 하나의 방향을 유지하며 길이를 1로 만든다. (3,4)와 (0.6,0.8)은 같은 반직선 위에서 같은 쪽을 가리키며 끝점과 길이가 다르다. 인스턴스 메서드이므로 별도 인자 없이 자신의 X,Y를 사용한다.
- 현재 2D `Normalized()`는 영벡터를 그대로 반환한다. 이는 코드의 정책이며 반환값이 단위 벡터라는 의미는 아니다.
- `Vector3D.UnitNormal(a,b)`는 두 입력에 수직인 외적을 구해 그 길이를 1로 만든다. 학습자의 “방향을 1로”라는 표현을 “길이를 1로”로 교정했고, 학습자가 이해를 확인했다. 이름은 UnitNormal로 유지한다.
- 2D 왼쪽 단위 법선 (-y,x)/|v|는 설명과 예제만 제시했다. `Vector2D.UnitNormalLeft()` 및 `Vector3D.Normalized()`는 이번에 구현하지 않았다.

## 실행과 범위

`dotnet run --project PointVectorPractice/PointVectorPractice.csproj`로 실행한다(.NET 10). 현재 Program.cs에서 활성화된 검증은 정상 입력, 거의 평행 입력, 100만 배 입력이다. 이전 역순·평행·반평행·영벡터 실습 코드는 주석으로 보존되어 있다. 최종 커밋 전 활성 코드의 빌드·실행을 다시 확인했다.

이번 구현은 학습에서 사용한 유한한 크기의 입력을 대상으로 한다. NaN/Infinity, 극단적 크기의 overflow/underflow, 허용오차 경계 바로 위·아래 검증은 수행하지 않았다. 새 OCCT 실행이나 좌표계 변환 검증도 하지 않았다.
