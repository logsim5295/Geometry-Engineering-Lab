# 실습 01 · Point와 Vector, 이동 원리

**상태:** 2026-10-29 학습자가 기존 코드의 점−점·점+벡터 및 정규화를 직접 실행. 점−벡터 실행과 OCCT 이동 코드 확인 남음. **시간:** 30~60분 × 3회(첫 회차는 아래 C# 검증).

## 해결하려는 문제

CAD 형상의 위치와 이동량을 구분하고, 이미 수행한 형상 이동을 수학적으로 설명한다. 기존 Point2D/Vector2D를 다시 만들지 않는다.

## 핵심 수학

점은 위치, 벡터는 변위와 방향·크기를 나타낸다. `B−A=v`, `A+v=B`이다. `p'=p+t`에서 p는 점이고 t는 이동 벡터다. 점+점은 이 모델에서 제공하지 않는다. 원점에서 점까지의 위치 벡터는 선택한 좌표계에 의존한다.

벡터는 평행 이동으로 바뀌지 않는다. 크기가 0인 벡터에는 방향이 정의되지 않는다. 현재 `Vector2D.Normalized()`는 영벡터를 그대로 반환하므로 이 결과를 단위 방향으로 사용하면 안 된다.

## 구현 방법과 C# 예제

별도 임시 콘솔 프로젝트에서 기존 `01-3D-Math.csproj`를 참조하고 아래를 `Program.cs`로 사용한다. 기존 라이브러리 프로젝트에 top-level 코드를 직접 넣지 않는다. 기존 프로젝트는 `net10.0`이다.

```csharp
using _01_3D_Math;

static void Near(double actual, double expected)
{
    if (!double.IsFinite(actual) || Math.Abs(actual - expected) > 1e-9)
        throw new Exception($"Expected {expected}, got {actual}");
}

var a = new Point2D(1, 2);
var b = new Point2D(4, 6);
var displacement = b - a;
var moved = a + displacement;
Near(displacement.X, 3);
Near(displacement.Y, 4);
Near(displacement.Length(), 5);
Near(moved.X, b.X);
Near(moved.Y, b.Y);
Near(Point2D.Distance(a, b), 5);
Near(displacement.Normalized().Length(), 1);
Near(new Vector2D(0, 0).Normalized().Length(), 0); // 현재 구현의 정책
Console.WriteLine("Point / Vector checks passed.");
```

예제의 `1e-9`는 작은 좌표의 수치 실습 기준이며 실제 CAD 모델에 일괄 적용하는 tolerance가 아니다.

## OpenCascade 적용

적용함. 기존 형상 이동 예제를 재사용한다.

- gp_Pnt: 위치를 표현한다.
- gp_Vec: 크기가 있는 벡터이며 이동량을 표현할 수 있다.
- gp_Dir: 단위 방향을 표현한다. 영벡터로 방향을 만들지 않는다.
- gp_Trsf: 이동 변환을 정의하고 점/형상에 적용한다.

OCCT 버전 및 C# 바인딩이 아직 확인되지 않았으므로 실행 가능한 C# OCCT API 호출을 가정하지 않는다. 사용한 래퍼의 메서드와 공식 API를 대응시킨 뒤 원래 이동 코드에 주석을 추가한다.

### 2026-10-27 · 공통 학습 기록

Point는 위치, Q-P는 크기·방향을 가진 이동량임을 설명했다. (3,0,0)+(0,4,0)=(3,4,0)의 길이 5와 개별 길이 합 7을 구분했고, (13,2,0)-(10,0,0)=(3,2,0)을 계산했다. (-6,8,0)의 길이 10과 단위 방향 (-0.6,0.8,0), 지정 거리 이동도 직접 답했다. 이에 따라 P1-02는 완료로 기록한다.

영벡터에는 단위 방향이 없고 수학적으로 정규화할 수 없음을 확인했다. **기존 Vector2D.Normalized()가 (0,0)을 반환하는 것은 API의 처리 정책이며, 길이 1인 단위 벡터를 구했다는 뜻이 아니다.** 이번 대화의 예외 발생 예제와 기존 코드 정책은 구분해 후속 테스트한다.

평행이동 p+t·반대 이동과 상대 위치 보존을 학습했다. gp_Vec/gp_Dir의 역할도 설명했으나 gp_Pnt·gp_Trsf 및 코드 사용 설명은 보완한다. C#·OCCT 신규 실행 결과는 없으며 P1-01/03/04/06은 진행 중이다. 상세 답변과 근거는 [Progress](Progress.md)에 있다.

### 2026-10-29 · 학습자 직접 실행 및 손계산

A=(1,2), B=(4,6)에 대해 B−A=(3,4), 길이 5, A+(B−A)=(4,6), A−B=(−3,−4)를 계산하고 점−점 결과는 Vector2D, 점±벡터 결과는 Point2D임을 확인했다. 점−벡터는 코드를 읽고 계산했으며 아직 직접 실행하지 않았다.

학습자가 기존 프로젝트를 참조한 별도 C# 콘솔을 직접 실행해 다음 출력을 확인했다.

```text
B - A = (3, 4)
이동 벡터의 길이 = 5
A + (B - A) = (4, 6)
정규화 = (0.6, 0.8), 길이 = 1
영벡터 정규화 = (0, 0), 길이 = 0
```

영벡터 반환은 기존 코드의 처리 정책이고 단위 방향은 아님을 설명했다. t=(10,0,0)으로 점 p=(1,2,3)을 옮겨 (11,2,3)을 구하고 방향 벡터는 변하지 않는다고 답했다. A=(1,2,0), B=(4,6,0)을 같은 t로 이동하면 A′=(11,2,0), B′=(14,6,0), B′−A′=(3,4,0)임을 계산했다.
