## 손계산과 교정

로컬 축의 월드 방향은 +X→+Y, +Y→−X, +Z→+Z이다.

| 내용 | 학습자 답변 | 확인 |
|---|---|---|
| 단위축 표현 | ex=(0,1,0), ey=(-1,0,0), ez=(0,0,0) | ex/ey 정답. ez는 (0,0,1)로 교정. 영벡터에는 방향이 없음을 설명 |
| O=(10,0,0), 로컬 (3,2,1) → 월드 | (8,3,1) | 제시된 일반식에 대입해 정답 |
| 위 월드 점을 로컬로 복원 | (3,2,1) | v=(−2,3,1)과 각 축의 내적 식을 제공한 뒤 정답 |
| ex·ey, ex의 길이 | 0, 1 | 수직·단위길이 확인. 나머지 축 쌍의 독립 검증은 남음 |
| ex=(0,2,0), v=3ex=(0,6,0)에서 v·ex | 12, 원래 계수 3이 나오지 않음 | 정답. 수직인 비단위축에서는 (v·ex)/(ex·ex)로 보정함을 설명 |
| O=(5,-2,1), 월드 P=(1,4,3) → 로컬 | v=(-4,6,2), 로컬 (6,4,2) | 학습자 손계산 정답 |

정규직교 기저에서 Pw=O+x ex+y ey+z ez, v=Pw−O, Pl=(v·ex,v·ey,v·ez)를 학습했다. 내적으로 성분을 바로 얻으려면 모든 축이 서로 수직이고 길이가 1이어야 한다. 비직교 축에는 위 길이 보정만으로 역변환할 수 없다.

마지막 예제의 월드 복원 (5,-2,1)+6(0,1,0)+4(-1,0,0)+2(0,0,1)=(1,4,3)은 설명자가 제시했다. 학습자 정방향 코드 실행으로 집계하지 않는다.

## 코드 구현과 학습자 실행

실제 저장소는 Geometry-Engineering-Lab이며 솔루션 이름은 3D-Engineering-Study.slnx이다.

- [Point3D.cs](https://github.com/logsim5295/Geometry-Engineering-Lab/blob/main/01-3D-Math/01-Primitives/Point3D.cs): double 기반 readonly record struct. 원점, 점−점→Vector3D, 점±Vector3D→Point3D, 거리·거리제곱, ToVector를 작성했다.
- [Vector3D.cs](https://github.com/logsim5295/Geometry-Engineering-Lab/blob/main/01-3D-Math/02-Vector/Vector3D.cs): 기존 Dot을 사용하고 LengthSquared를 추가했다. 벡터끼리의 덧셈·뺄셈 구현과 점끼리의 뺄셈은 구분한다.
- [Coordinate/Program.cs](https://github.com/logsim5295/Geometry-Engineering-Lab/blob/main/Coordinate/Program.cs): world=(1,4,3), origin=(5,-2,1), 위 세 단위축을 사용했다. 학습자가 world-origin=(-4,6,2), local=(6,4,2)를 직접 실행해 보고했다.
- 코드 검토에서 Point3D.ToVector가 Vector2D(X,Y)를 반환해 Z를 버리는 문제를 발견했다. 학습자가 `public Vector3D ToVector() => new(X,Y,Z);`로 수정했고 소스를 다시 확인했다. Coordinate는 ToVector를 호출하지 않으므로 해당 메서드의 실행 검증과는 구분한다.
