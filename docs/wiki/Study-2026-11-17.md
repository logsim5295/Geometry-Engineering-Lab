# 2026-11-17 · CoordinateSystem3D와 좌표 왕복 검증

[Home](Home.md) · [진행도](Progress.md)

학습자의 설명·직접 실행 보고와 코드 검토·도구 재실행을 구분한다. 원점은 O=(5,-2,1), 기본 월드 점은 P=(1,4,3)이며 아래 별도 표시한 로컬 점을 제외하면 이 입력을 사용했다.

## 학습 흐름과 이해 확인

1. ToWorld의 성분식을 작성하고 월드→로컬→월드 복원을 실행했다. 원점을 더하는 이유를 학습자가 설명했고, 로컬 원점에서 점까지의 변위에 로컬 원점의 월드 위치를 더한다는 표현으로 정리했다.
2. ToWorld와 ToLocal을 독립 함수로 분리했다. 내적으로 좌표를 얻는 ToLocal은 정규직교 축을 전제로 한다.
3. 소수 성분의 축에서 작은 반올림 오차와 허용오차 비교를 확인했다. 왕복 오차는 원래 점과 복원한 점 사이의 거리이며 이번 실습의 절대 거리 허용오차는 1e-10이다.
4. 길이 2인 축에서 역변환 전제가 깨지고 큰 오차가 발생하는 것을 확인했다. LengthSquared()의 출력 4를 길이라고 표현한 부분은 길이 제곱 4, 실제 길이 2로 교정했다.
5. 모두 길이 1인 축도 내적이 0이 아니면 수직이 아님을 학습자가 설명했다. 각 축 길이 제곱과 1의 차이, 세 축 쌍의 내적 절댓값을 1e-10과 비교하는 IsOrthonormal을 작성했다. 축 검사 허용오차와 점 사이 거리 허용오차는 같은 숫자를 썼지만 검사 대상이 다르다.
6. ToLocal 시작에서 잘못된 축을 거부한 뒤 CoordinateSystem3D 생성자로 검사를 옮겼다. 읽기 전용 Origin/AxisX/AxisY/AxisZ 속성과 ToLocal/ToWorld 인스턴스 메서드로 정리했다.
7. 일반적인 3D 축 배치에서 로컬→월드→로컬 순서도 검증했다.

## 일반적인 3D 축의 로컬→월드→로컬

```text
a=1/sqrt(2), b=1/sqrt(6), c=1/sqrt(3)
ex=(a,a,0), ey=(-b,b,2b), ez=(c,-c,c)
원점 O=(5,-2,1), 원래 로컬 점=(2,-3,4)

월드 좌표: Point3D { X = 9.948359510523188, Y = -4.119932385776997, Z = 0.859911333975325 }
복원한 로컬 좌표: Point3D { X = 2, Y = -3.000000000000001, Z = 4.000000000000001 }
왕복 오차: 1.2560739669470201E-15
허용오차 이내: True
```

축 정의와 예제는 설명자가 제공했고 학습자가 직접 실행해 보고했다. 모든 가능한 입력의 검증이나 행렬 구현 완료로 확대 해석하지 않는다.
